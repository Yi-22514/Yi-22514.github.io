动手搭建大模型个人学习总结

学习 Happy-LLM 第五章时，我最明显的感受是：只有真正把 LLaMA 这类模型拆成代码模块，才会发现大模型并不是一个不可触碰的整体。它依然是由 Embedding、Attention、Feed Forward、Norm、输出头这些模块拼起来的，只是每个模块的设计都更适合大规模训练和生成任务。

这一章对我最大的帮助，是把“我知道 Transformer”推进到了“我能看懂一个 LLM 的核心实现”。

一、从结构上理解 LLaMA

LLaMA 系列模型本质上是 Decoder-only Transformer。它的训练目标是因果语言模型，也就是根据上文预测下一个 token。和原始 Transformer 相比，LLaMA 在很多细节上做了现代化改造，比如 RMSNorm、RoPE、SwiGLU、KV Cache 等。

这些改造看起来分散，但它们的目标很统一：让模型在大规模训练和长文本生成中更稳定、更高效。

二、Tokenizer 是模型和文本之间的桥

以前我容易忽略 tokenizer，总觉得它只是“分词”。但学习这一章之后，我意识到 tokenizer 是文本进入模型之前最重要的接口。

模型本身并不直接处理中文、英文或符号，它处理的是 token id。Tokenizer 负责把文本编码成 token id，也负责把模型输出的 token id 解码回人类能读的文本。

对大模型来说，Tokenizer 会影响很多事情：

  • 词表大小会影响 Embedding 参数量。
  • 子词切分会影响稀有词和多语言文本的表示。
  • 特殊 token 会影响指令数据的组织方式。
  • 编码效率会影响同样上下文长度下能放入多少信息。

所以 tokenizer 不是附属工具，而是模型能力边界的一部分。一个不合适的 tokenizer，可能会让模型在某些语言或符号场景中效率很低。

三、RMSNorm、RoPE 和 SwiGLU

LLaMA 中有几个结构值得重点记住。

RMSNorm 是一种归一化方法，它不像 LayerNorm 那样减去均值，而是使用均方根进行缩放：

$$RMSNorm(x)=\frac{x}{\sqrt{\frac{1}{n}\sum_i x_i^2+\epsilon}}\odot g$$

它的计算更简洁，也适合大规模模型训练。

RoPE 是旋转位置编码。它不是简单把位置向量加到 token embedding 上，而是在 Attention 的 Q、K 上引入旋转变换，让模型更自然地建模相对位置信息。对我来说，RoPE 的重要性在于它让位置信息和注意力计算绑定得更紧。

SwiGLU 是前馈网络中的激活结构。相比普通 FFN，它通过门控方式控制信息流动，让模型表达能力更强。很多现代 LLM 都使用类似的 GLU 变体。

这些细节让我明白，大模型性能的提升不只是“堆层数”，也来自大量经过验证的小结构优化。

四、预训练：让模型学会续写

从零训练一个小型语言模型时，最基本的任务就是 next token prediction。给定一段 token 序列，输入是前面的 token，标签是右移一位后的 token。

模型每一步都在学习预测下一个 token。这个目标很简单，但因为可以从海量无标注文本中自动构造训练样本，所以非常适合大规模预训练。

预训练阶段的目标不是让模型成为聊天助手，而是让模型获得通用的语言建模能力。它学到的是词语搭配、语法结构、事实知识、代码模式以及大量文本规律。

五、SFT：让模型学会按指令回答

预训练后的模型会续写，但不一定会听话。比如用户问“请解释 Transformer”，一个纯预训练模型可能会继续写一段类似网页文本，而不是给出结构化回答。

SFT 的作用就是把模型调整成指令响应模式。训练数据通常由 instruction、input、output 组成，模型学习在给定指令和上下文后生成期望答案。

我觉得 SFT 的关键点有两个：

  • 数据格式要稳定，让模型知道哪里是用户问题，哪里是助手回答。
  • Loss 通常更关注回答部分，避免模型把提示模板本身也当成主要学习目标。

这让我意识到，模型“会聊天”不是预训练自然带来的，而是经过指令数据重新塑形之后的结果。

六、我的阶段性理解

这一章让我对“搭建大模型”这件事少了很多距离感。虽然真正训练大模型需要很高的算力，但理解它的核心结构并不一定要从百亿参数开始。先用 PyTorch 写一个小模型，跑通 tokenizer、模型结构、预训练和 SFT，反而更能看清每个模块的作用。

我现在觉得，动手实现的意义不在于马上训练出一个强模型，而在于建立一张内部地图：文本怎样变成 token，token 怎样进入 Embedding，位置怎样进入 Attention，模型怎样预测下一个 token，指令数据又怎样把模型变成助手。

有了这张地图，再去看 LLaMA、Qwen、DeepSeek 这些模型时，就不会只看到一个名字，而能大致知道它们背后有哪些组件可以比较、替换和优化。
