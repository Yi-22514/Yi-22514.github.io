预训练语言模型个人学习总结

学习 Happy-LLM 第三章之后，我对预训练语言模型的理解变清楚了很多。以前我只是知道 BERT、GPT、T5 这些名字，但没有真正把它们放到 Transformer 的结构里统一比较。现在再看，它们其实都是在回答同一个问题：Transformer 的 Encoder 和 Decoder 到底该怎么用，才能最适合不同的 NLP 任务？

这一章给我的最大收获是：预训练语言模型不是某一个模型，而是一套从“模型架构”到“预训练任务”再到“下游迁移”的方法论。

一、预训练语言模型解决了什么问题

传统 NLP 模型往往是针对某一个任务单独训练，比如情感分类训练一个模型，实体识别再训练一个模型。这样的问题是：每个任务都需要不少标注数据，模型也很难把从一个任务中学到的语言知识迁移到另一个任务。

预训练语言模型的思路是先在海量无监督文本上学习通用语言表示，再用少量有监督数据适配具体任务。也就是常说的：

这种范式的核心价值在于，模型在预训练阶段已经学到了词法、句法、语义甚至部分世界知识，下游任务只是在这个基础上做定向调整。BERT 之后，NLP 的很多任务都从“从零训练”变成了“拿一个预训练模型来微调”。

二、Encoder-only：以 BERT 为代表的理解型模型

BERT 选择的是 Transformer 的 Encoder 部分，也就是 Encoder-only 架构。Encoder 的特点是每个 token 可以双向关注上下文，因此非常适合理解类任务，比如文本分类、情感分析、自然语言推理、实体识别等。

BERT 的核心预训练任务是 MLM，也就是 Masked Language Model。它会随机遮住输入中的一部分 token，让模型根据上下文把它们预测出来。这个任务有点像完形填空，重点不是生成下一句话，而是理解当前位置和上下文之间的语义关系。

我现在对 BERT 的理解是：它更像一个“语义编码器”。输入一句话之后，它会给每个 token 生成带上下文的表示，再用 [CLS] 位置或 token 级 hidden states 去完成分类、匹配、标注等任务。

BERT 之后还出现了很多改进版本。RoBERTa 去掉了 NSP 任务，使用更大数据、更大 batch 和动态 mask 来增强训练；ALBERT 通过 Embedding 分解和跨层参数共享减少参数量，并提出 SOP 任务来增强句子顺序建模。这些改进让我意识到，模型能力并不只由结构决定，数据规模、训练任务和训练策略同样关键。

三、Encoder-Decoder：输入到输出的转换模型

Encoder-Decoder 保留了原始 Transformer 的完整结构。Encoder 负责理解输入序列，Decoder 负责根据 Encoder 的表示生成输出序列。这种结构天然适合 Seq2Seq 任务，比如机器翻译、摘要生成、问答生成等。

T5 是这一类思想的代表。它把各种 NLP 任务统一成 text-to-text 格式，也就是“输入文本，输出文本”。比如分类任务不再输出一个类别 id，而是直接生成“positive”或“negative”这样的文本标签。

这个设计让我很受启发：很多任务之所以看起来不同，是因为我们人为定义了不同的输出形式。如果统一成文本生成，模型就能用同一套输入输出接口处理很多任务。

Encoder-Decoder 的优势是输入理解和输出生成分工清晰，但它的结构也更重。相比 Decoder-only 模型，它在大规模开放式生成上的路线没有 GPT 系列那么直接。

四、Decoder-only：以 GPT 为代表的生成型模型

GPT 选择的是 Transformer 的 Decoder 部分，也就是 Decoder-only 架构。它使用因果语言模型任务进行预训练，核心目标是根据前面的 token 预测下一个 token：

$$P(x_t|x_1,x_2,\ldots,x_{t-1})$$

这个任务看起来简单，但非常贴合文本生成。只要模型学会不断预测下一个 token，它就可以自然地完成续写、问答、摘要、代码生成等任务。

Decoder-only 的关键是 Mask Self-Attention。模型在当前位置只能看到过去，不能看到未来，因此训练目标和推理时的生成方式是一致的。这一点是 GPT 路线能持续扩展到大语言模型的重要原因。

我现在对 GPT 的理解是：它不是为了某一个下游任务设计的，而是把所有任务都转化为“给定上下文后继续生成”。这也是为什么 Prompt 在 LLM 时代变得这么重要，因为任务说明、示例、输入内容都可以作为上下文的一部分交给模型。

五、三类架构的对比

从学习角度看，我可以这样区分三类模型：

  • Encoder-only：擅长理解，代表模型是 BERT，适合分类、匹配、抽取、标注。
  • Encoder-Decoder：擅长输入到输出的转换，代表模型是 T5、BART，适合翻译、摘要、结构化生成。
  • Decoder-only：擅长开放式生成，代表模型是 GPT、LLaMA、Qwen 等，是当前 LLM 的主流路线。

这并不是说某一种结构绝对更强，而是它们的归纳偏置不同。BERT 倾向于把文本编码成强语义表示，GPT 倾向于把任务放进上下文里继续生成，T5 则试图用统一的文本到文本框架组织任务。

六、我的阶段性理解

学完这一章之后，我感觉预训练语言模型的发展路线很像一棵树。Transformer 是根，BERT、T5、GPT 是三条主要枝干。它们都来自同一个基础架构，但因为选择了不同的结构组件和训练目标，最终长成了完全不同的模型生态。

在 LLM 时代，Decoder-only 的 GPT 路线成为主流，但这并不代表 BERT 失去了价值。对于很多高吞吐、低延迟、标注数据充分的理解任务，BERT 系模型依然很实用。对我来说，真正重要的是理解任务本身需要“理解表示”“序列转换”还是“开放生成”，再选择合适的模型范式。

这一章也让我意识到：LLM 不是凭空出现的，它是预训练语言模型路线不断放大之后的结果。下一步学习大语言模型时，就不能只看参数规模，还要继续追问它继承了什么训练目标、什么架构选择，以及为什么这些选择能被规模放大。
